## 2. הארכיטקטורה שנבנתה בפועל

```
פיירברי  ──v3, דלתא לפי modifiedon──►  fb-sync (Edge Function)
                                              │ UPSERT
                                              ▼
                                     Postgres · 19 טבלאות מראה

                                              │
                                              ▼
                                     dash-api (אימות + JSON מצטבר)
```

**שינוי מהתוכנית:** שכבת ה-ETL נבנתה על **Supabase Edge Functions + pg_cron** ולא על n8n, כי אין מפתח SSH פרטי ל-VPS (רק הציבורי נמצא ב-ClickUp). **זהה תפקודית.** מעבר ל-n8n בעתיד לא נוגע בדשבורד — רק מחליף מי קורא לפיירברי.

## 5. שישה גילויים טכניים חדשים מהביצוע

### 5.1 ✅ המבנה המדויק של `POST /api/v3/query` — סוגר סתירה פתוחה מס' 1 בפלייבוק

```json
{ "objectType": 1051,
  "fields": [{"name":"name"},{"name":"pcfStatus"}],
  "pageSize": 500, "pageNumber": 1,
  "filter": [{ "type":"and", "conditions":[
     {"fieldName":"modifiedon","operator":"ge","value":"2026-08-01 00:00:00"}]}] }
```
תשובה **שטוחה**: `{data:[…], success, pageNumber, pageSize, isLastPage}`.
ה"עטיפה הכפולה" שתועדה בפלייבוק היא **ארטיפקט של Make, לא של ה-API.**

### 5.2 🔴 מפתח בקשה לא מוכר — פיירברי **מתעלם ממנו בשקט**
`sort`, `query`, `filters` כולם החזירו `200 OK` עם **כל** הרשומות. אין שגיאה, אין אזהרה.
**כלל:** כל שאילתה מסוננת חדשה עוברת בדיקת שלילה לפני שסומכים עליה. `sort` **אינו נתמך** — ממיינים אצלנו.

### 5.3 🔴 מפתח התווית של `ownerid` **משתנה בין אובייקטים**
אובייקט **4** מחזיר `ownername`. אובייקט **1051** מחזיר `owneridname`. מיפוי שמניח אחד מהם מייצר **עמודה ריקה בלי שגיאה** — בדיוק מה שקרה, וזוהה רק בבדיקת דפדפן.
**הפתרון שנבנה:** טריגר `fill_owner_label` על 7 טבלאות, שמשלים את התווית מתוך `raw` בכל insert/update. עמיד גם לשינויים עתידיים בפיירברי.

### 5.4 🔴 `1039.pcfNextPaymentDate` מפיל את פיירברי ב-**HTTP 500**
השדה קיים במטא-דאטה, אבל שאילתה עליו מחזירה `Internal Server Error` — גם לבדו. הוצא מהמיפוי.
**נבנתה הגנה כללית:** אם התשובה מכילה `Invalid field: X` — השדה מוסר אוטומטית והשאילתה רצה מחדש. שדות שהוסרו נרשמים ב-`sync_log.detail`.

### 5.5 שדות שלא קיימים למרות שנראו קיימים
`1.pcfCity` → אין (יש `billingcity`) · `67.name` → אין (יש `campaignname`) · `9.systemuserid` → אין (יש `crmuserid`, אבל `_id` עובד תמיד).

### 5.6 `POST /api/query` (Legacy) **כן** מחזיר `isrequired` / `isreadonly` / `maxlength`
בבלוק `Columns[]`. הפלייבוק קובע שאלה "אינם נחשפים ב-API כלל" — **לא מדויק.** אפשר לייצר את טבלת שדות החובה אוטומטית במקום לספור ידנית.

## 6. תפעול — איך עושים דברים

### החלפת סיסמת הדשבורד
```sql
-- מריצים ב-SQL Editor של הפרויקט. החלף PASSWORD.
update app_config set value = encode(digest(
  (select value from app_config where key='auth_salt') || 'PASSWORD','sha256'),'hex')
where key='auth_sha256';
```
(דורש `create extension if not exists pgcrypto;` פעם אחת.)

### הפעלת סנכרון ידנית
דרך הדשבורד — כפתור **"סנכרן עכשיו"**. או:
```
POST https://klobimzmuurzbimfkubr.supabase.co/functions/v1/fb-sync
header: x-sync-secret: <sync_secret מ-app_config>
body:   {"full": true}     ← משיכה מלאה במקום דלתא
```

### עדכון הדשבורד (קובץ ה-HTML)
הקובץ יושב ב-Storage bucket `dash`. **כתיבה אנונימית סגורה** — צריך לפתוח policy זמנית, להעלות, ולסגור. או פשוט להעלות ל-SFTP של ויטרו.

### שינוי מדד / הוספת מדד
כל הלוגיקה ב-`index.html` בבלוק `VIEW.<tab>`. אין build step, אין תלויות — עורכים ומעלים.

### 🔴 רוטציית טוקן פיירברי
הטוקן **נחשף בצ'אטים ובמסמכי הפרויקט. חובה רוטציה לפני מסירה ללקוחה.** אחרי הרוטציה — **4** מקומות:
1. חיבורי Make · 2. credential ב-n8n · 3. `1036.pcfPowerlinkToken` · 4. `app_config.fireberry_token` בפרויקט הזה.
