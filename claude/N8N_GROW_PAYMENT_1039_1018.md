## 🔴🔴 ממצא קריטי — תחביר סינון שגוי ב-`/api/v3/query` מחזיר רשומות שגויות בשקט

**זה הממצא החשוב ביותר בסשן. רלוונטי לכל workflow בפרויקט.**

התחביר הזה **אינו תקין** ופיירברי **לא מחזיר עליו שגיאה** — הוא פשוט **מתעלם מהסינון ומחזיר את הרשומות הראשונות במסד**:

```json
"query": [[{ "a": "telephone1", "o": "=", "b": "0542776161" }]]
```

בהרצה חיה: חיפוש לפי הטלפון `0542776161` (טל ויטרו) החזיר את **"יונית דהן"** — לקוחה אקראית.
זה גרוע יותר מ"אפס תוצאות בשקט" המתועד בפלייבוק — כאן חוזרות **תוצאות שגויות** שנראות תקינות לחלוטין.

**התחביר הנכון — אומת חי:**

```json
"filter": [
  { "type": "and", "conditions": [
      { "fieldName": "telephone1", "operator": "eq", "value": "0542776161" }
  ]}
]
```

- `type` = `"and"` או `"or"` — **שניהם אומתו חי**. `or` משמש ל-`telephone1 OR telephone2`.
- **שם שדה שגוי בתוך `filter` כן מחזיר 400** (`Invalid field: zzzNotAField`) — כלומר הסינון עצמו בטוח, רק התחביר השגוי מסוכן.
- `fields` **חייב** להיות מערך אובייקטים `[{"name":"..."}]` — מחרוזת נכשלת ב-400.
- `orderBy: [{"name":"createdon","order":"desc"}]` — **עובד**. `sortBy`/`sortType` **לא עובד** ונכשל בשקט.
- תשובה **לא עטופה כפול**: `data:[...]` ישירות (בקריאה ישירה, לא דרך Make).

**פעולה נדרשת (בעלים: מייק/אליאל):** לסרוק כל workflow/מפרט קיים בפרויקט שמשתמש ב-`query:[[{a,o,b}]]` מול v3 — סביר שהם שולפים רשומות שגויות עכשיו.
